# 変更履歴

装飾・整形プラグイン（`decoration-formatter`）の改修履歴です。

> **引き継ぎメモ**
> 別のチャット／担当者に作業を引き継ぐときは、まず `README.md`（機能概要）と
> このファイル（改修履歴）を読んでください。各エントリには変更したファイル名を
> 併記しているので、コードのどこを触ったか追跡できます。
> このプラグインはバージョン管理（git）下になく、配布zipが唯一の成果物です。

フォーマットは [Keep a Changelog](https://keepachangelog.com/ja/1.1.0/) に準拠し、
バージョンは [セマンティック バージョニング](https://semver.org/lang/ja/) に従います。

## [1.0.28] - 2026-09-04

### 修正
- **「？」「。」の直後に閉じカッコが続く文を、そこで切ってしまう不具合を修正**
  （`includes/paragraph-formatter.php`）。
  - 「しかし『価格が安い分、効果も薄いのでは？』『体に悪くない？』と不安を感じる方も
    少なくありません。」のような文が、句点の直後で必ず分割されていたため、
    閉じカッコだけが次の段落の先頭に落ちて「」と不安を感じる方も…」という
    段落ができていた（かぐあし本番で43記事・60箇所）。
  - 文の区切りを探す正規表現に否定先読みを足し、閉じカッコ・句読点
    （`」』）〉》】］｝”’〟、。！？!?,.`）が続くあいだは切らないようにした。
  - 読点での強制分割（`force_split_chars` 超過時）にも同じ判定を入れた。
  - 判定文字は `decofmt_fmt_closing_chars()` にまとめてある。

## [1.0.27] - 2026-09-01

### 追加
- **段落整形（一括）に「絞り込み」を追加**。従来は「投稿の全記事」しか対象にできなかった。
  - **投稿タイプ**を選べるようにした（投稿／固定ページ／公開中のカスタム投稿タイプ）。
    投稿と固定ページは混ぜず1種類ずつ処理する。切り替えると自動で再スキャンする。
  - **カテゴリ**で絞り込めるようにした（複数選択＝いずれかに属する記事／子カテゴリも含む）。
    未選択なら全カテゴリ。固定ページのようにカテゴリを持たない投稿タイプでは
    チェックボックスを自動で無効化し、条件として使わない旨を画面に出す。
  - 一覧に**「種別」列**を追加し、スキャン完了メッセージにも実際の絞り込み内容
    （投稿タイプ／カテゴリ件数／モード）を出すようにした。
  - 「全件に適用」の確認ダイアログに投稿タイプ名を入れた。
  - 変更ファイル: `admin/formatter-bulk.php` / `admin/ajax-handler.php` /
    `includes/paragraph-formatter.php`（`decofmt_fmt_get_post_types()` /
    `decofmt_fmt_get_post_type_label()` を追加）
- **固定ページの編集画面にも「📝 段落整形」メタボックスを表示**するようにした
  （AI装飾側は元から post/page 両対応だったので、整形側を揃えた）。
  変更ファイル: `admin/formatter-meta-box.php`

### 変更
- スキャンのクエリを `post_type='post'` 固定の直SQLから `get_posts()` + ID一括取得に変更。
  カテゴリ（tax_query）に対応させるため。本文取得は1クエリのままなので記事数が多くても重くならない。
  変更ファイル: `admin/ajax-handler.php`

### 補足（意図的に変えていない点）
- 設定画面の「投稿保存時に自動で整形する」は**従来どおり投稿（post）のみ**に効く。
  固定ページはLP等でブロック構造が固いことがあり、保存のたびに自動整形が走ると事故になるため、
  固定ページは一括画面／メタボックスからの明示的な実行だけにしている。

## [1.0.25] - 2026-07-09

### 修正（バグ・重要）
- **「。で区切る（1文ごとに改行）」モードが実際には動いていなかった問題を修正**。
  v1.0.8 でこのモードを追加した際、`preg_replace_callback` のクロージャに
  `$settings` を `use` で渡し忘れていた。PHPのクロージャは外側の変数を自動では
  引き継がないため、**実処理側では常にOFF扱い**になっていた。
  一方カウンタ側は `$settings` を正しく参照するため、
  「3句以上短段落 23件」と表示されるのに **変換0件・残23件** という
  食い違いが起きていた。
  判定をクロージャの外で行い `use` で渡すように修正。
  — `includes/paragraph-formatter.php`

### 内部
- 同種のバグ（クロージャへの変数キャプチャ漏れ）が他に無いか、
  全PHPファイルのクロージャを機械的に走査して確認（該当0件）。
  PHPのlintでは検出できない種類のバグのため、目視ではなく機械的に洗った。

## [1.0.24] - 2026-07-09

一括装飾が50件全滅（前半=タイムアウト、後半=HTTP 400）した件の対処。
原因になりうる箇所を3つ潰し、**原因が見えるように**した。

### 修正（バグ）
- **`max_tokens` を記事の長さから算出するよう変更**（従来 32000 固定）。
  Anthropic のレート制限（OTPM）は実際の生成量ではなく **`max_tokens` で予約した量**を
  消費する。32000 固定だと 3並列で毎分96,000トークンを予約することになり、
  上限に当たって待たされ、240秒でも足りず `cURL error 28` でタイムアウトしていた。
  装飾は「元の本文＋装飾タグ」なので入力の2.5倍で足りる（下限4000）。
  `decofmt_max_tokens` フィルタで調整可。
  — `includes/claude-api.php`

- **リトライ時に検証エラーのHTMLをPOSTしていたのをやめた**。
  v1.0.23 で `retry_feedback` として `<!-- wp:paragraph -->` 等を含む文字列を
  ブラウザ→サーバーへ送っていた。これがレンタルサーバーのWAFに
  「XSS/PHPコマンド」と判定され、**admin-ajax が HTTP 400 で拒否される**原因に
  なっていた可能性が高い（検知後に同一IPを一定時間ブロックする挙動と、
  途中から全件400になった症状が一致する）。
  修正指示はサーバー側の transient に保存し、ブラウザは `retry=1` フラグだけ送る。
  エラーメッセージも `wp_strip_all_tags` を通してから返す。
  — `admin/ajax-handler.php` / `admin/decoration-bulk.php` / `assets/admin.js`

- **同時実行数の既定を 3 → 2 に変更**。APIレート制限に当たりにくくする。
  説明文にも「上げるとレート制限で かえって遅くなる」旨を追記。

### 改善（原因が見えるようにする）
- **エラー表示を実用的にした**。従来は「HTTP 400」としか出さず原因が追えなかった。
  - レスポンスがJSONならサーバーのメッセージを表示
  - HTMLエラーページなら `<title>` を抽出して併記
  - 400/403 は「WAF／セキュリティプラグインがブロックしている可能性」と明示
  - 行の赤文字にマウスを乗せると**全文**が出る
  - **ブラウザのコンソール（F12）に生のレスポンスを最大2000文字出力**
- **連続5件失敗したら一括処理を中止する**サーキットブレーカーを追加。
  APIキー切れ・残高不足・WAFブロックは続けても全部失敗するため、
  残りを無駄に消費しない。中止時はその旨と調べ方を画面に表示する。

## [1.0.23] - 2026-07-09

### 修正（バグ・重要）
- **504 Gateway Timeout を修正**（XSERVER 等で発生）。
  原因は**1リクエストが長すぎたこと**。サーバー（PHP）側でリトライループを
  回していたため、`API呼び出し最大300秒 × 最大3回 = 最大900秒（15分）`を
  1本の admin-ajax リクエストで処理しようとし、サーバーのプロキシに切られていた。
  （v1.0.17 でタイムアウトを 180→300 秒に上げたことで悪化していた）
  - **リトライをブラウザ側に移動**。サーバーは **1リクエスト＝API 1回** だけ叩く。
  - 検証エラーの内容はレスポンスで返し、ブラウザが `retry_feedback` として
    送り返して再試行する（モデルへの修正指示は従来どおり機能する）。
  - 一括処理・メタボックスの両方に適用。最大3回試行は変わらない。
  - **APIタイムアウトを 300 → 240 秒に変更**。共有サーバーのプロキシ上限
    （多くは300秒前後）に対して余裕を持たせる。タイムアウトしても
    ブラウザ側で再実行できるので短めでも取りこぼさない。
  - `includes/decorator.php`（`max_retries` / `retry_feedback` オプション追加）
  - `includes/claude-api.php` / `admin/ajax-handler.php` / `admin/decoration-bulk.php` / `assets/admin.js`

- **504 のエラー画面がそのまま alert に出る問題を修正**。
  サーバーが返す HTML のエラーページを丸ごと表示していた（数百行のHTMLがダイアログに出る）。
  ステータスコードから短い日本語メッセージに変換して表示するようにした。
  - 504「サーバータイムアウト。処理が長すぎたためサーバーが接続を切りました」
  - 502 / 503 / 接続断 もそれぞれ判別
  - 一括処理では alert を出さず、該当行のボタン位置にインライン表示（60件処理で
    alert が連発するのを防ぐ）

### 追加
- API タイムアウトを `decofmt_api_timeout` フィルタで調整可能にした（既定240秒、30〜300秒の範囲）。
  例: `add_filter('decofmt_api_timeout', function () { return 200; });`

## [1.0.21] - 2026-07-09

### 修正（バグ）
- **`<li><strong>ラベル</strong>／説明文</li>` が整形されない問題を修正**。
  区切り文字としてコロン（`：` `:`）しか見ていなかったため、

  対応する区切り文字を拡張:
  - コロン: `：` `:`
  - スラッシュ: `／` `/`
  - 縦棒: `｜` `|`
  - ダッシュ類: `―` `—` `–` `−` `-`
  - ラベルのタグも `<strong>` に加えて `<b>` に対応

### 内部
- **同じ正規表現が2箇所にコピペされていた問題を解消**。
  「実際に分割する処理」と「件数を数えるカウンタ」で別々に定義されており、
  片方だけ直すと「検出したのに変換されない／その逆」という噛み合わないバグに
  なる構造だった（過去に複数回発生）。`decofmt_fmt_strong_label_pattern()` に
  集約して構造的に再発を防止。

  完全に1句ずつ分割**するよう変更。counter 側の simulate も同じロジックに揃えた。
  結果、適用後の counter が確実に 0 まで下がる。
  — `includes/paragraph-formatter.php`

## [1.0.11] - 2026-07-09

### 修正（バグ）
- **タグバランスチェックで HTML コメントを 'open' 扱いしていた問題を修正**。
  段落内に `<!-- xxx -->` があると stack が上がりっぱなしで全セグメントがマージされ、
  「候補 N 件検出したが変換 0 件」になる可能性があった。
  v1.0.9 で balance check を導入した際の考慮漏れ。
  - HTML コメントを `self` 扱いに変更（開閉に影響しないタグ）

### 変更
- **`add_heading_spacing` / `add_media_spacing` の空段落挿入を撤廃**。
  H2/画像/表の直前に `<p></p>` を差し込む処理を止めた（Gutenberg エディタで
  「ブロックを選択するには「/」を入力」の空ブロックとして視認されて邪魔だった）。
  見出し前後の余白は現代の WP テーマなら CSS で十分取れているのでプラグイン側で
  介入しない。設定項目「見出し前後の余白」「画像・表前後の余白」は互換のため
  残るが実効なし（no-op）。既に挿入された空段落は残るので、必要なら手動削除を。

— `includes/paragraph-formatter.php`

## [1.0.10] - 2026-07-09

### 修正（バグ）
- **`<!-- wp:paragraph -->` の2重wrapping**（Gutenberg「無効なコンテンツ」エラー）を修正。
  `add_heading_spacing` / `add_media_spacing` が H2/画像/表の前に

  - — `includes/paragraph-formatter.php`

**⚠️ 既に壊れた記事**: WPリビジョン（投稿編集画面 → 右サイドバー → リビジョン）から
分割前の版に戻すのが安全。または Gutenberg 側の「復旧を試みる」ボタンで自動修復も可能な場合あり。

## [1.0.7] - 2026-07-09

### 修正（バグ）
- **「11件検出→変換2件、残9件」の非対称バグを解消**。v1.0.6で追加した multi_sentence_short
  counter は「3句以上あるか」だけを見ていたが、`split_inner` が各セグメント `min_sentence_chars=60`

    カウント。**counter = 実際の変換数**、を保証
  - 60字未満の3句パラ（例: 「はい。ええ。それで。」）は分割意義がないので候補から除外
  - — `includes/paragraph-formatter.php`

## [1.0.6] - 2026-07-09

### 修正（バグ）
- **「短めだが句点3個以上」の密な段落を分割対象化**（処理・スキャン・UI・delta 全ラインを一括対応）。

  過剰分割は起きない。

    `multi_sentence_short` カウンタ追加
  - `admin/ajax-handler.php` — スキャンの対象判定と apply の delta 計算に反映
  - `admin/formatter-bulk.php` — 一括処理表に「3句以上短段落」列追加、delta 合計計算に反映
  - `admin/formatter-meta-box.php` — 投稿編集画面のメタボックスに表示追加

## [1.0.0] - 2026-07-07

### 追加（初版・統合）
以下の2つの独立プラグインを統合し、Affirosブランドを除去した汎用プラグインとして再構成した初版。
DBPテーマ用ブロック生成前提は継続。自動更新機能（Affiros9サーバー参照）は削除。

**AI装飾（旧 `affiros-decoration` v1.2.1 由来）**
- Claude API による記事本文の自動装飾（マーカー・赤字・強調ボックス・アイコンリスト等）
- 装飾レベル3段階（軽め/標準/盛り盛り）、モデル4種選択可
- ロールバック機能（自動バックアップ）
- バリデーション（ブロック構文・文字数比較・H2保持）
- 検証エラー時にモデルへエラー内容をフィードバックして自動リトライ
- 絞り込み一括処理（カテゴリ・タグ・装飾状況）
- 処理ログ＋モデル別集計＋ログ全削除ボタン
- 個別記事の除外フラグ

**段落整形（旧 `affiros-paragraph-splitter` v1.1.1 由来）**
- 長段落の分割（句点・接続詞・強制分割しきい値）
- 句読点連続の正規化
- 見出し昇格（正規表現パターン + 文字数閾値）
- リスト内 `<strong>ラベル</strong>：長文` の見出し+段落分解（親見出しレベル+1で階層化）
- H2/H3・画像・表前後の空段落挿入
- 全記事スキャン→ before/afterプレビュー→ 個別/一括適用
- 保存時自動整形オプション

### 変更（統合に伴う内部リファクタ）
- ディレクトリ・スラッグ: `decoration-formatter`
- 全定数・関数プレフィックスを新体系に統一
  - 定数: `DECOFMT_*`（VERSION, PATH, URL）
  - 装飾側関数: `decofmt_deco_*` / クラス `Decofmt_*`
  - 整形側関数: `decofmt_fmt_*`
  - オプションキー: `decofmt_deco_settings` / `decofmt_fmt_settings`（分離保持）
  - 投稿メタ: `_decofmt_*`
  - AJAX nonce: `decofmt_nonce`（統一）
  - AJAXアクション: `decofmt_deco_*` / `decofmt_fmt_*`
- 管理画面をトップメニュー「装飾・整形」1本に統合
  - 設定（統合画面・2フォーム）／ AI装飾（一括）／ 段落整形（一括）／ 処理ログ
- 投稿編集画面のサイドバーに両方のメタボックスを表示（🎨 AI装飾 / 📝 段落整形）
- 統合設定画面：AI装飾と段落整形を1画面2フォームで管理

### 削除
- **自動更新機能（`affiros-paragraph-splitter` の `includes/plugin-updater.php`）** を削除
  - Affiros9 サーバー（wp-manager.onrender.com）依存を排除
  - 更新は zip の手動アップロード運用に統一
