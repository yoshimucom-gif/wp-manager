## 設計上の要点

- WP REST API を使わず `WP_Query` / `wp_update_post` で完結 → ホスティングの WAF・海外IP制限による 403 を回避する（これがプラグインの存在理由）。
- Claude APIキーは `wp-config.php` の定数 `AFFIROS_REWRITE_API_KEY` を最優先で使う。定義されていれば管理画面DBより優先され、プラグインの更新・再インストールでも消えない。
- 一括リライトは確認画面を経由せず順次保存する。ただし壊れた内容でライブ記事を上書きしないための安全弁あり（v0.4.0 参照）。
- リライト結果は `wp_update_post` 経由で保存 → WordPress のリビジョンで復元可能（リビジョン無効サイトでは画面に警告を出す）。

## バージョン履歴

### v0.4.0 (2026-05-22)
**削除**
- 品質プリセット機能（`quality-presets.php` / `presets-page.php` と関連コード）。未使用だったため削除し、リライトのオプションは「設定画面の既定値」＋「記事タイプ指定」に集約。

**安全性強化（一括リライトのデータ破損リスクを解消）**
- Claude の出力が想定フォーマット（`===TITLE===` / `===CONTENT===`）で返らない場合、`WP_Error` で中断し保存しない（前置き混入などの混濁テキストでライブ記事を上書きしない）。
- 出力が出力上限で途中切れした場合（`stop_reason=max_tokens`）も中断。
- 元記事が 30000 字を超える場合は中断（末尾を失ったまま上書きするのを防ぐ）。
- `max_tokens` を目標文字数から動的算出（固定値8000による長文の途中切れを解消）。
- リビジョンが無効なサイトでは、リライト画面に上書き前の警告を表示。

**修正**
- Haiku のモデルIDを正規の `claude-haiku-4-5-20251001` に修正（旧 `claude-haiku-4-5` 等は読み込み時に自動マイグレーション）。

**整理**
- 未使用の `get_post` AJAXエンドポイントを削除。
- 中身が空だった `admin.js` を削除（`wp_localize_script` は jQuery 経由に変更）。
- 設定画面の誤った説明文を修正。

### v0.3.2 (2026-05-22)

## 既知の制約・今後の検討事項

- **長文記事のタイムアウト**: Claude の応答がホスティング（ConoHa 等）の PHP / プロキシ制限を超えると「通信エラー」で失敗しうる。一括実行では Haiku・少数バッチが安全。
- **元記事の上限**: 30000 字。超える記事はリライトを中断する。
- **画面JS**: `rewrite-page.php` にインライン（約260行）。必要なら `admin.js` へ分離可能。
- **アンインストール**: `uninstall.php` は無し。設定（APIキー等）を意図的にDBへ残す方針のため。
